# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # Next.js dev server (localhost:3000)
npm run build        # production build
npm run lint         # eslint (flat config: next core-web-vitals + typescript)
npm run test:e2e     # Playwright e2e suite (e2e/)
npx playwright test e2e/plasma-sizing.spec.ts          # single spec file
npx playwright test -g "plasma keeps rendering"        # single test by title
npx playwright show-report                             # HTML report in e2e-report/
```

The site is a regular Next.js app hosted on **Netlify** (`netlify.toml`; Netlify's Next.js support runs it, route handlers become functions, and `next/image` goes through Netlify Image CDN). All pages still prerender as static HTML; only `app/api/contact/route.ts` runs on demand. The Playwright `webServer` runs `npm run build && npm run start -- -p 3100` (`reuseExistingServer: false`), so tests always hit a fresh production build, never the dev server. Tests run serially (1 worker, Chromium only). The config's `storageState` starts every test with analytics refused (`jk-consent`), so the cookie banner stays out of the way; `e2e/consent.spec.ts` resets it to test the banner.

There are no unit tests; the e2e suite is mostly regression/perf checks (console errors, duplicate ids, memory/WebGL/rAF leaks across client-side navigation, Plasma CPU usage, SPA navigation). `e2e/instrument.ts` is injected via `page.addInitScript` to count live rAF loops, WebGL contexts, intervals and listeners; `e2e/helpers.ts` holds the shared route list (`PAGES`). `PERFORMANCE_REPORT.md` documents past bugs and the reasoning behind many of the current fixes — read it before reworking animation/WebGL lifecycle code.

## Architecture

Next.js 16 App Router + React 19 + Tailwind v4 portfolio/landing site. Path alias `@/*` → repo root.

- **Route groups**: `app/(smooth)/` holds all real pages (`/`, `/about`, `/projects`, `/contact`) and wraps them in `LenisProvider` + `Navbar` + `Footer`. Pages are server components; interactivity lives in small client components (`components/home/Hero.tsx`, `Statement.tsx`, `Navbar.tsx`, `ContactForm.tsx`, `Projects/*`).
- **Root layout** (`app/layout.tsx`): one variable font (Archivo, `wdth` axis 62–125; display sizes use `wdth` 75) self-hosted via `next/font`, an inline script that adds `html.js` before paint (CSS hides `[data-intro]` elements only when JS runs, with a 2.5s CSS fallback), skip link, consent-gated analytics (`components/Analytics.tsx` renders GTM + GA4 via `@next/third-parties` only once `lib/consent.ts` says `granted`; `components/CookieBanner.tsx` asks, with equal Allow/Refuse buttons; the footer's `CookieSettingsButton` reopens it; withdrawing deletes `_ga*` cookies and reloads), `next-themes` provider (class-based, default light, system disabled), and the global `TargetCursor` (fine pointers only, off under reduced motion; markup always rendered for hydration safety).
- **Smooth scroll + GSAP**: `providers/LenisProvider.tsx` creates one Lenis instance, sets up `ScrollTrigger.scrollerProxy(document.body, …)`, and drives both `lenis.raf` and `ScrollTrigger.update()` from a single rAF loop. Access it with `useLenis()`. It also handles same-page hash links itself (scroll, focus, and `history.pushState` so the entry carries Next's router state); don't re-enable Lenis' `anchors` option, because native fragment navigation creates null-state history entries that the App Router ignores on Back. Always import GSAP from `@/lib/gsap` (registers `ScrollTrigger` and `SplitText` client-side only).
- **Animation lifecycle is the main source of bugs.** Pages fully remount on client-side navigation, so every GSAP tween/timeline/ScrollTrigger must be cleaned up (`gsap.context()` + `ctx.revert()`, or `tl.kill()`) in the effect cleanup. In effects, capture DOM nodes into local consts rather than re-reading `ref.current` in callbacks/cleanup (React nulls refs before cleanup runs).
- **Plasma** (`components/Plasma/`): OGL WebGL shader behind the home hero. It pauses via IntersectionObserver and `visibilitychange`, caps FPS, respects `prefers-reduced-motion`, and explicitly calls `WEBGL_lose_context` on unmount (Chromium caps live contexts at 16; leaking them blanks the canvas after a few navigations). When it does not render (reduced motion, or no WebGL) it sets `data-fallback` and CSS draws a static lilac stand-in. It is loaded with `next/dynamic` (`ssr: false`). Keep these behaviours when editing.
- **Page transition**: `components/PageTransition.tsx` (mounted in the `(smooth)` layout after the page) claims internal link clicks in the capture phase (next/link then skips them), prefetches, and runs `lib/pageTransition.ts`. The curtain is the layout grid: 12 columns (6 under 768px), lilac leading indigo, rising in a wave from the click's x position, *under* the site header (z 58 vs 60; header text turns white via `html.pt-header`, and a single `.site-nav-indicator` slides between nav links). The old page drifts up (transform) and is dimmed by an overlay scrim, never `opacity` on `<main>`; its h1 lines exit upwards. Under cover the route changes; the new `main h1` is cloned onto the curtain (registered on its first glyph, block-level lines split separately), clipped to the indigo still covering it, so it hands over column by column as the columns lift and the page settles up from below (page and copy share one tween). GSAP owns the column transforms (no CSS transform on them). Clicks during a transition are queued (latest wins). Skipped for back/forward, same-page links, `data-story` rows and `data-no-page-transition`; reduced motion gets a 150ms fade. `isPageCovered()`/`PAGE_COVER_EVENT` hold the Plasma still from click to the end of the reveal (it draws one warm-up frame under the curtain); `isPageTransitionActive()` lets the hero skip its headline intro and the mobile menu close instantly. `data-page-lead` marks the paragraph that settles in after the reveal. e2e: `clickNav` waits for the transition to finish.
- **Navigation**: `components/Navbar.tsx` renders inline links at ≥768px and a full-screen GSAP menu dialog below that (`inert` when closed, Escape closes, focus managed). Nav items, contact details and socials live in `lib/site.ts`. Internal links must use `components/TargetCursor/CursorLink.tsx` (wraps `next/link`) so nav stays client-side; plain `<a>` only for external links.
- **Projects**: content lives in `data/projects.ts` (`ProjectStory` with typed `slides`; accent colours are chosen to pass AA with white text). Each project gets a generated pattern (`lib/patterns.ts`, seeded by its id) from one of five families (maze, arcs, circuit, triangles, plots), set per project with the `pattern` field in `data/projects.ts` (otherwise picked from the id); families repeat once there are more than five projects, but neighbouring projects must not share one (the contrast spec checks this); it is shown on its story slides, `/projects` tile, work-row hover and the transition overlay via the `--pattern`/`--pattern-size` variables from `patternStyle()`. Lines are always a *darker* shade of the accent, so text contrast can only rise; `e2e/pattern-contrast.spec.ts` enforces this for every project, so a new accent must pass AA with white on its own. Each family has its own pattern-to-accent contrast in `PATTERN_CONTRAST` (filled shapes get less, to look equally quiet). The home page lists them in `components/home/WorkIndex.tsx`, linking to `/projects?story=<id>`, which opens that story. With motion allowed, that link runs a cross-route shared-element transition (`lib/storyTransition.ts`): a body-level overlay clips the row's accent colour open into the story frame, the route changes once the page is covered, and `ProjectsRoot` opens the story instantly underneath and hands off; closing a story entered this way runs it in reverse via `router.back()` into the same row. On `/projects` itself, clicking a tile runs a same-page variant (`playTileEnter`/`playTileReturn` in the same file): a copy of the tile grows into the story frame (its chapter bars stretch into the progress bars, details fade), the story opens instantly underneath (the tile's slot stays empty while it's open), and closing shrinks it back into the tile and refocuses it. Reduced motion and deep links skip it. The story-frame geometry in that file mirrors `lib/swiper/stories-slide.css`, so keep them in sync. `/projects` shows a Swiper row of tiles (its `slidesPerView`/`spaceBetween` breakpoints are mirrored in `ProjectsRoot.css` under `:not(.swiper-initialized)` so the server-rendered first paint is already card-sized; change both together) and a story viewer built on a vendored Swiper "stories slider" (`vendor/swiper/` → wrapped by `lib/swiper/`; all callback props must be stable or the slider is re-created). `ProjectsSlider` makes it a modal dialog (focus, arrows/Space/Escape, `inert`, Lenis stop). A story never moves on to another project (`lockStory`, a local option added to the vendored slider): its last chapter is the call to action, autoplay stops there and the story stays open until the visitor closes it (✕/Escape, or tapping past the last chapter). When that chapter's time is up (`onComplete`) it becomes an end card: its copy moves to the centre (GSAP, reverted on any chapter change) and the pattern fades out. Focus follows chapter changes to the visible slide's close button, since each slide has its own. The button links to `/contact?project=<id>#project-form`, where `ContactForm` pre-fills the subject and focuses the first field. Slides render via `components/Projects/SlideRenderer.tsx`; each chapter type has one entrance, the same in every project (`components/Projects/chapterMotion.ts`, keyed by `data-chapter`), played on every chapter change and reverted (SplitText included) when leaving it; skipped under reduced motion. Never put React inline styles on a `.swiper-slide`: Swiper's `destroy()` removes the slide's `style` attribute whenever the slider is re-created (React dev double effects do this), so per-slide colour and pattern live on the inner `.story-surface` element instead.
- **Home page structure**: `app/(smooth)/page.tsx` follows a conversion order: `Hero` → `Proof` (`#work`: testimonials with each result painted in its project's accent/pattern, then `WorkIndex`) → `Problem` (pains, their cost, the `Statement`, then features with `FeatureFigure` line drawings) → `HowItWorks` (4 steps; a scroll-scrubbed progress rule) → `Faq` (native `<details>`) → `CtaBand` (takes `title`/`lead` props). Section copy lives in `data/home.ts`; its testimonials, result figures and FAQ terms are **filler** (bracketed placeholders) to replace with real content. Keep the hero's content shorter than the viewport at 1280×720 (`plasma-sizing.spec.ts` checks the hero height is stable). Because `#work` sits above the testimonials, `completeStoryReturn` re-corrects the row's position a frame after the router's hash scroll.
- **Legal pages**: `/privacy`, `/cookies`, `/terms`, `/security`, `/licenses` share `components/LegalPage.tsx` (contents list + sections, styles in `LegalPage.css`), are linked from the footer's Legal nav (`legalItems` in `lib/site.ts`) and listed in the sitemap. Bracketed values (legal name, providers, retention periods, governing law) are placeholders for the business to confirm. Keep `/cookies` in step with what the site actually stores, and `/licenses` in step with `package.json` and the font. `public/.well-known/security.txt` has an `Expires` date to renew yearly.
- **Contact**: `components/ContactForm.tsx` (react-hook-form) posts to `/api/contact` (`app/api/contact/route.ts`, a Netlify Function in production; works in `next dev` too). The route checks the origin (against the `Host`/`x-forwarded-host` header, not `req.url`, which `next start` rebuilds from its own hostname), size, a hidden `website_url` honeypot, the four required fields and the optional company, phone (normalized to E.164), service interest and budget range (choices in `lib/contactOptions.ts`), then forwards them server-to-server to `${CONTACT_API_URL}/contact-submissions` with `X-Api-Key: ${CONTACT_API_KEY}`, the visitor's address as `X-Client-Ip` (from `x-nf-client-connection-ip`) and browser as `X-Client-User-Agent`, plus `source_page` from the same-site referrer. The backend trusts those headers only after the key matches and rate-limits per visitor. Laravel needs no CORS and its URL and key never reach the browser. Errors come back as `{ message, errors? }`; per-field `errors` (its own or Laravel's 422) are shown on the fields, and upstream failures are a generic 502 with details only in the server log. `e2e/contact-function.spec.ts` drives it against a fake Laravel on :3199 (`webServer.env` in the Playwright config).
- **Styling/theme**: Tailwind v4 configured in CSS. `app/globals.css` defines the design tokens as CSS variables on `:root`/`.dark` (exposed to Tailwind via `@theme inline`: `bg-paper`, `text-ink`, `text-muted`, `border-line`, `bg-band`, …) plus shared classes (`.shell`, `.grid-12`, `.t-display`/`.t-h1`/`.t-h2`/`.t-h3`/`.t-lead`, `.btn-*`, `.link`, `.field`). Some components ship their own `.css` file alongside. Icons are inline `currentColor` SVGs in `components/Icon.tsx`.
- **SEO**: `lib/seo` is the source of truth. `SITE_URL` is `https://www.jkrafts.com` (Netlify's primary domain; the bare domain 308s to it) and is used for every canonical, Open Graph URL, sitemap entry and JSON-LD, whatever host serves the build. `isIndexable` is true only when Netlify builds with `CONTEXT=production` (or `SEO_INDEXABLE=true`); otherwise (deploy previews, branch deploys, local builds) robots.txt disallows everything, the robots meta is `noindex, nofollow` and `next.config.ts` adds `X-Robots-Tag: noindex`. Every page must export `pageMetadata({ title, description, path })`; don't hand-write `openGraph` on a page, because Next replaces rather than merges it. The home page carries Organization + WebSite JSON-LD (`components/JsonLd.tsx`). The sitemap lists the 9 indexable pages (no query variants, no `lastModified`). `npm run seo:audit -- <url> [--mode preview]` (`scripts/seo-audit.mjs`) crawls any copy of the site; `e2e/seo.spec.ts` runs it on every test run, and the Playwright build uses `CONTEXT=production`. Results and the deployment phases are tracked in `docs/seo/seo-report.md`.
